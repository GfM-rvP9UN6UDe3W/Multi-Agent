# SPEC-0008: Confirmed Claude interruption

Date: 2026-09-20. Status: implemented; offline process, bilingual lifecycle, installed SDK transport and native-type checks passed. Real CLI/model acceptance remains pending. See [verification evidence](../tdd/0008-claude-interruption.md).

## Problem and scope

The original orchestration design includes Claude Query.interrupt and interrupt-mode pause/modify/cancel. The adapter currently advertises interruption as unsupported and uses a string prompt. Implement the intended capability in Multi-Agent only. Do not modify Axion, invoke paid models, read credentials, publish, commit, or push.

This specification supersedes the Claude unsupported-interruption clauses in SPEC-0002 and SPEC-0007. Their stop-proof, permission, usage, and unknown-outcome requirements remain in force. Existing engine control operations, wire protocol, and persistence schema remain unchanged.

## Runtime contract

- Advertise `interrupt: true`. Each dispatch uses native streaming input with exactly one user message and a unique UUID. Keep the input open until terminal observation or cleanup. Resume uses the same native session ID; a new dispatch gets a new input stream and UUID. Do not introduce concurrent prompts or a second scheduler.
- The adapter owns `includePartialMessages: true` so it can observe turn activity. Host options cannot replace this setting. A matched main-thread assistant or stream event establishes turn activity. An init event, prompt delivery, or interrupt acknowledgement alone does not establish that a running turn was interrupted. If cancellation arrives during startup, defer the interrupt until activity is observed, within the original acceptance/turn and interrupt budgets. Never blindly retry an interrupt.
- Input AbortSignal before submission prevents query creation. After submission it requests native interruption once without immediately aborting the SDK controller or abandoning the result iterator. Native Query.interrupt resolution is only a request acknowledgement. A missing method, thrown/rejected request, or lost acknowledgement is not confirmed interruption; keep observing for independently conclusive terminal evidence within the same bounds.
- A matched result with structured `terminal_reason` equal to `aborted_streaming` or `aborted_tools` maps to the existing `interrupted` terminal. Do not infer interruption from error strings, an arbitrary error result, input AbortSignal, stream EOF, process exit, or an interrupt receipt. Ordinary failures remain failures. A successful result winning the cancellation race remains a result and follows the engine's existing control semantics.
- Introduce positive integer `interruptTimeoutMs` (default 30 seconds). Its monotonic deadline begins when cancellation is requested after submission, including startup delay, and never resets. Observation uses the minimum of this budget and the existing acceptance/turn budget. Engine control deadlines remain authoritative for business outcomes and may expire earlier; late matched evidence can release execution capacity but cannot silently clear quarantine or retry work.
- Resource shutdown uses the SDK AbortController/close and the existing owned-process cleanup after terminal observation or deadline, independently of the interrupt receipt. A matching terminal plus independently observed local process exit is required for the default restricted profile. Expanded options/write execution additionally requires the existing positive host stop observer. No terminal or unconfirmed cleanup retains unknown outcome and execution ownership. Preserve late terminal and usage observations for the original dispatch.
- The public injected query interface exposes optional `interrupt()` for compatibility with existing noninterrupting offline factories. Such a factory cannot confirm active interruption without native terminal proof. Production relies on the installed native SDK's Query.interrupt, streaming input, and structured result fields; unsupported/absent terminal reasons never become synthetic success.

## Acceptance criteria

- **AC-I01 Streaming ownership:** capability is true; an actual offline child consumes one typed streaming prompt; input stays open; model/cwd/resume/UUID and owned partial-message option are correct. Host overrides are rejected. Pre-submission cancellation sends nothing.
- **AC-I02 Confirmed control:** native interrupt is called exactly once after turn activity, including cancellation before init/activity. Its acknowledgement does not abort the SDK controller or produce a terminal. Matching structured abort results plus process exit finish pause/cancel; usage remains available. Successful result and unrelated-error races preserve their actual outcomes.
- **AC-I03 Failure boundaries:** hanging/rejecting/missing interrupt, no terminal, wrong session, stream EOF, arbitrary error text, and unconfirmed local cleanup never fabricate interrupted or release execution without proof. Cancellation while waiting on the next iterator result wakes the bounded deadline check. Expanded execution requires its observer. Late terminal/usage observations retain their original identity and do not undo expired controls.
- **AC-I04 Lifecycle integration:** real offline subprocesses through the public TypeScript and Python clients exercise interrupt pause, resume, cancel, and modify/context delivery. Resume/modify preserve native session identity, generations and single-dispatch ownership. A lost/expired control acknowledgement preserves blocked/quarantined state without resubmission.
- **AC-I05 Evidence:** record meaningful RED/GREEN evidence; run Node/Python suites, typecheck, formatting and diff checks. Where available, verify the actual installed native SDK's stream/control transport against an offline subprocess fixture without using native login/model execution. Distinguish this from real CLI/model acceptance, which remains separately authorized.

## Native evidence and non-goals

The official [streaming input documentation](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode) distinguishes streaming input's real-time interruption from a string prompt. The installed native SDK types/source can verify the Query.interrupt control surface and structured terminal reasons; these are version-coupled facts, not proof of provider execution. No generic tool-confirmation wire protocol, provider history reconciliation, background-work stop assumption, or automatic unknown retry is added.
