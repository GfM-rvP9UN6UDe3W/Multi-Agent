# SPEC-0007: Host policy injection and durable usage observations

Date: 2026-09-20. Status: implemented and verified with offline fixtures; native-runtime/model acceptance remains pending. Verification: [TDD evidence](../tdd/0007-host-policy-and-usage.md). Builds on [SPEC-0006](./0006-host-runtime-contract.md) and [A2](./0003-a2-execution-isolation.md).

## Problem and scope

The standalone adapters hard-code a read-only tool/policy surface. Claude's public request type cannot express a host's native options. Its failure-result branch discards reported usage, and cleanup uncertainty can discard even observed successful usage. The engine exposes task usage reads but does not publish durable usage notifications. An ordinary callback alone cannot provide restart-safe delivery to a host ledger.

This increment adds embedded adapter policy/options injection, opt-in workspace-write execution, explicit Codex network/search settings, conservative stop observation for extended execution, and durable usage observations accessible through both SDKs. Keep default permissions restrictive. Do not modify another application, call real models, read credentials, publish, push, or implement a second tool-confirmation UI. Existing application-owned adapters remain the preferred integration path for a host that already owns runtime policy and auditing.

## Host options and permissions

- Claude accepts typed `options` and an optional `extendOptions(context)` callback. The generic options parameter preserves native host callback/MCP/settings types without an `any` cast. The context carries immutable dispatch identity, requested permission profile, and the original remaining budget. An async extension consumes the existing acceptance/total budget; failure or timeout before submission must not invoke the query factory.
- Model, cwd, resume/session identity, abort controller, process-spawn ownership, and prompt are adapter-owned. Reject attempts to replace those fields at typecheck and runtime, including overrides returned by the extension. Host options may supply tools, allowedTools, disallowedTools, permissionMode, settingSources, hooks, canUseTool, MCP servers, system prompt, maxTurns, settings/managedSettings, and environment. Do not serialize function-valued options onto the wire or persist private options in events/errors.
- `permissionProfile` config defaults to `read-only`; an adapter only advertises its configured profile and rejects a different input profile before acquiring resources. Default Claude read-only tools remain Read/Glob/Grep. Workspace-write defaults add Edit/Write/Bash. Tool arrays, setting sources, permission mode, and maxTurns receive runtime validation. Unknown/native option types remain the caller's responsibility and are checked by the caller's installed native SDK type.
- Claude always composes a built-in pre-tool guard with host hooks. Read-only rejects built-in mutating tools; workspace-write restricts built-in file edits to the canonical workspace. Protect the engine state directory from native file reads/searches/writes. Resolve existing symlinks and nonexistent-target ancestors before checking paths. Deny malformed path inputs, unsandboxed Bash, and explicit background Bash. Custom/MCP tool authority remains the trusted host's responsibility.
- Workspace-write Bash requires native sandboxing with `enabled`, `failIfUnavailable`, and no unsandboxed fallback. Host settings may tighten the sandbox but may not widen its writable roots beyond the workspace or remove the state-directory deny. SDK scratch-directory behavior and actual platform enforcement still require native-runtime acceptance; protocol fixtures alone are not that proof.
- Host tool approval uses its own hooks/canUseTool and native permission mode. When canUseTool is supplied without an explicit allow list/mode, use an empty allow list and interactive/default permission mode. Preserve explicit host choices. Task result approval remains independent.
- Codex config accepts `permissionProfile`, `networkAccess`, and `webSearch` (`disabled`, `cached`, or `live`). Default read-only/no-command-network/search-disabled is explicit. Map profile into both thread start/resume and turn sandbox policy. Workspace-write uses the canonical workspace as the sole explicit writable root and excludes general temporary roots. Search and command network settings are independent, including on resumed threads. Keep isolated managed home and native-feature restrictions.
- Callback/options injection and workspace-write integration are embedded TypeScript features. The JSON CLI continues rejecting workspace-write and function/native options until it has a suitable host policy/stop implementation. The CLI may expose the serializable Codex network/search controls. Do not imply Python JSON configuration can transport host callbacks.

## Execution scope and cancellation

The unsupported Claude interruption statements in this historical increment are superseded by [SPEC-0008](./0008-claude-interruption.md). Its native interrupt implementation retains all full-stop observation and usage requirements below.

The unextended read-only adapters retain their existing minimal execution coverage. A write profile or extended Claude native options cannot inherit that full-execution assumption. Its native terminal proves the main turn ended, not that host/MCP/background work ended.

Expose a host `observeExecutionStop(context)` callback for expanded execution. Its true result is an explicit host observation of complete remote/background execution stop for the exact dispatch/generation; false, missing, rejection, or timeout is not stop proof. Invoke only after a matched native terminal; observe it within the bounded cleanup budget, retain late positive evidence, and combine it with independently observed local cleanup. Never treat callback completion as local process exit. Without complete proof, preserve unknown outcome/occupied execution and the existing reconciliation path. The observer receives identity and terminal evidence, not credentials or private options.

When an observer is configured, the adapter terminal-coverage capability denotes the combined matched terminal plus positive host observation and independent local exit. Native-terminal evidence alone retains unknown remote execution.

Claude continues to advertise `interrupt: false`; active task cancel/control must reject UNSUPPORTED_CAPABILITY without aborting execution. Owner resource shutdown remains distinct. Do not advertise Query.interrupt merely because an upstream SDK exposes a method. Codex retains its existing bounded native interrupt/stop-evidence behavior. No generic tool approval request/reply wire protocol is introduced.

## Usage persistence and replay

- A matching Claude terminal reports its usage independently of success/failure and local cleanup success. Preserve reported fields and raw usage; unavailable fields stay null. Session-mismatched terminals cannot contaminate another dispatch. Capture late terminal usage after iterator observation timeout when the retained observation sees it.
- Introduce an optional `RuntimeInput.reportUsage` callback for observations that outlive the main iterator. The engine always supplies it. It uses the original dispatch closure and accepts observations for that retained durable dispatch without reviving tasks, releasing leases, or retrying execution. Existing yield-only adapters and standalone callers remain compatible.
- Persist usage and one `usage.recorded` event atomically. Identity remains `dispatchId:usageId`; callback plus yielded event or exact replay records it once. Conflicting contents for the same identity reject rather than overwrite a ledger record. Validate token fields/raw JSON before persistence. Do not expose model options or credentials in errors.
- The event references usage record ID, dispatch ID, provider, and normal task/session envelope metadata. It need not duplicate potentially large raw payloads. Add `usage.getRecord` plus TypeScript `usage.getRecord(id)` and Python `usage.get_record(id)` to retrieve one exact record. Existing `usage.get(taskId)` and its completeness semantics remain compatible.
- Hosts consume existing bounded `events.read` / events iterators with storeId and cursor. A host first commits its own outbox/ledger record and only then advances its checkpoint. Replay uses `(storeId, usageRecord.id)` as a stable deduplication key. Supply a runnable offline forwarding example that exercises a restart/replay without double accounting.
- This is durable publication of observations actually received by the engine, not a distributed transaction with an external ledger. Preexisting usage remains readable; existing historical rows are not silently backfilled into new events. Unreported provider usage after an abrupt process loss cannot be reconstructed; retain the unknown dispatch/usage completeness. It is not proof of per-native-request accounting when the provider only reports aggregate turn usage. Do not bill the same host-native usage again from its orchestration projection.

Wire protocol remains 1.0 and storage schema remains 2; new read method/events are additive. Update canonical schema definitions and cross-language fixtures. No new runtime dependency is required.

## Acceptance criteria

- **AC-P01 Typed native extension:** native-shaped hooks/canUseTool/MCP/settings/options reach the injected query factory without `any`; forbidden ownership fields fail negative compilation. Runtime forbidden/malformed config fails before query submission and never prints private values. Existing defaults remain read-only.
- **AC-P02 Per-dispatch options:** callbacks see exact identities/profile/original remaining budget, can return asynchronous options within that budget, and cannot reset identity/deadlines. Timeout/rejection/abort leaves no host submission. One dispatch cannot mutate the next dispatch's policy arrays/hooks.
- **AC-P03 Claude write boundary:** write profile exposes configured Edit/Write/Bash; actual guard calls permit in-workspace edits and deny outside/symlink/state paths, readonly mutations, unsafe background/unsandboxed Bash, and weakening sandbox overrides. Host pre/post hooks and confirmation callback are retained. Native enforcement is explicitly not claimed from fixtures.
- **AC-P04 Codex policy mapping:** a real offline app-server child inspects start, resume, and turn options for both profiles and independent command-network/search settings. Explicit roots and managed-home restrictions remain. Invalid config fails before spawn. Default CLI behavior is unchanged apart from explicitly disabled search; new JSON network/search settings are validated.
- **AC-P05 Stop proof:** an extended main result with no/false/hanging observer cannot release execution; matching positive observation plus actual local exit can. Late proof is retained without automatic business reconciliation. Observer failure cannot discard usage. Claude unsupported cancel remains an explicit rejection; Codex interrupt regression remains green.
- **AC-P06 Usage on failure:** identical usage in successful and failed Claude results produces identical token/raw records; cleanup uncertainty and a late matching terminal preserve observations. Mismatched sessions cannot leak usage. Missing token fields remain null. No paid/model calls in tests.
- **AC-P07 Atomic replay and conflicts:** callback plus yield and duplicate replay produce one row/event. Different payload under an existing ID is rejected with the original row/event unchanged. A database transaction failure cannot leave only the row or only its event. Late usage does not change terminal task state/lease occupancy.
- **AC-P08 Process/Python recovery:** close/restart a real local host after usage persistence; resume a saved event cursor and read exact records from TypeScript and a real Python subprocess. Wrong storeId fails. A failed delivery or replay cannot double-count the sample ledger. Invalid/missing record IDs have stable errors.
- **AC-P09 Evidence and docs:** document embedded vs CLI boundaries, native SDK version coupling, settings-source distinction, task/tool approval separation, unknown usage limits, and the scope of stop observers. Record RED/GREEN commands and real results; run full Node/Python suites, typecheck, format, and diff checks. No real application integration or native-model acceptance claim.
