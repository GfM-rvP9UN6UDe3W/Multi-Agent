# SPEC-0002: Minimal real-runtime adapters

Date: 2026-09-19. Status: protocol wiring and [SPEC-0003-A](./0003-a-lifecycle.md) bounded observation/resource cleanup are implemented; real-provider model acceptance is pending. The foundation contract is [SPEC-0001](./0001-foundation.md). This document covers `packages/adapter-claude` and `packages/adapter-codex`. Foundation tests are in `tests/contract/adapters.test.ts`; later lifecycle evidence is linked below. [A2](./0003-a2-execution-isolation.md) supersedes the historical 300-second deadlines with a shared total budget, defaulting to 1800 seconds for new turns.

## Goals and interface

Each adapter implements internal `RuntimeAdapter.execute(input): AsyncIterable<RuntimeEvent>`. This increment permits only `read-only`; `workspace-write` requests fail immediately. `resume` reuses the provider session when `providerSessionId` exists. Fork, compact, and tool bridges are explicitly unsupported. Construction and `capabilities()` do not read credentials, start processes, or invoke models. Only `execute()` touches the official runtime.

`accepted` requires explicit upstream evidence: Claude SDK `system/init.session_id` (or a terminal message with a session ID), or a successful Codex `turn/start` response. Process startup, successful `initialize`, or creating a Codex thread alone are insufficient. After submitting to Claude `query()` or Codex `turn/start`, stream/process disconnection without an upstream terminal event yields `error(outcome="unknown")`, even before acknowledgment, because execution may have occurred. A definite pre-submission failure yields `failed`.

## Claude Agent SDK

Call `query()` from the installed optional peer dependency `@anthropic-ai/claude-agent-sdk`. Tests inject a query factory and require neither login nor model spending. Each execution owns its stream handle; `resume` maps to `options.resume`. Configure `settingSources: []`, `tools: [Read, Glob, Grep]`, the corresponding allow list, `disallowedTools: [mcp__*]`, and `permissionMode: dontAsk`. Do not expose write or MCP tools. `interrupt` is currently `false`: AbortSignal or an SDK exception alone cannot prove upstream termination or fabricate interrupted. Cancellation before execution can prove non-submission.

A successful SDK `result` yields terminal `result`. Missing usage fields remain `null`; do not infer cost or zero usage. Extract the four token categories from terminal `usage`, deduplicated by `dispatchId:result`. A started query without terminal evidence remains unknown. The SDK is an optional peer dependency and is not loaded by offline tests. Real calls require a caller-installed compatible version and officially supported authentication.

A introduced monotonic limits; A2 now supplies a shared total budget, defaulting to 1800 seconds for new turns and including acceptance. requestTimeoutMs defaults to 30 seconds and cleanupTimeoutMs to one second. Ordinary messages do not renew deadlines. Timeout/cancellation triggers owned-query cleanup, but cancellation after submission does not establish confirmed interruption.

[SPEC-0004 AC-R04](./0004-runtime-reliability.md) corrects the earlier cleanup assumption: Query.close returning, iterator.return(done:true), and AbortSignal do not prove child-process exit. Record owned processes through the official spawnClaudeCodeProcess callback. Confirm a handle ended only after observing actual exit or a failed spawn that never produced a PID. Seal late spawning when cleanup begins, and require all handles to end. Unconfirmed bounded cleanup retains unknown state, rejects adapter.close, and keeps hasActiveResources(sessionId) true; late exit can update resource evidence. Deliver success and usage after local cleanup confirmation, while keeping local exit separate from remote terminal evidence or business acceptance. Injected query factories must provide observable processes through this callback; a no-op close no longer satisfies the test cleanup contract.

The R04 follow-up splits the existing cleanupTimeoutMs into half for SDK cleanup and half for owned stdin EOF/SIGTERM fallback and observed exit. Missing or failed close triggers fallback immediately. Do not depend on the SDK forwarding the signal or await a permanently pending close/return. Invalid returns still trigger fallback; refusal to exit remains unknown. A record with no observed spawn is not automatically released. Only an ended observation, sealed spawning, and an exact original target permit owner reconciliation to retire it after the attestation transaction commits, without generating resource_observation. A genuinely live process cannot bypass the guard through this interface.

## Codex App Server

Each execute starts a separate managed `codex app-server` stdio child, closed on completion, exception, or consumer iteration stop. By default, retain only startup environment `PATH`, `HOME`, and `TMPDIR`. Callers must explicitly provide credential-related `env`; the adapter does not copy login credentials. Regardless of supplied `env.CODEX_HOME` or `env.CODEX_SQLITE_HOME`, force both to the real `stateDir/runtime/codex` path. The adapter owns and restricts that directory and `config.toml`. Configuration contains an empty MCP server map and disables native multi-agent, apps, plugins, browser, computer use, image generation, and hooks. If existing configuration differs, fail before startup without overwriting it. Command-line options repeat known feature disables, including `multi_agent` and `multi_agent_v2`, set workspace/ancestor-project trust to `untrusted`, and explicitly pass `mcp_servers={}` to prevent project `.codex/config.toml` injection. Injectable `command` / `args` support offline fixtures; the real default is `codex app-server`.

Use bidirectional JSON-RPC over JSONL: `initialize`, `initialized`, `thread/start` or `thread/resume`, then `turn/start`. Both new and resumed threads use `sandbox: read-only` and `approvalPolicy: never`; turns also set `sandboxPolicy: {type: readOnly, networkAccess: false}`. Map only items, usage, and terminal notifications matching the current thread/turn. Unassociated messages and request-time buffered messages each have a 256-item bound; frames are at most 1 MiB. Historical defaults were 30 seconds per request and five minutes from acceptance to terminal, configurable through positive integer `requestTimeoutMs` / `turnTimeoutMs`; A2 now supplies the shared total budget. Timeout/overflow closes the connection; submitted turns remain unknown. Cleanup sends SIGTERM, waits up to one second by default, then SIGKILL and another second. `closeTimeoutMs` configures each stage. Even after upstream terminal evidence, unconfirmed owned-process exit yields unknown.

`turn/completed` status completed, failed, or interrupted maps to `result`, `error(failed)`, or `interrupted`. Once a turn ID exists, AbortSignal sends `turn/interrupt`, but only `turn/completed(status=interrupted)` confirms cancellation. Disconnection remains unknown. Extract final text from `item/completed(agentMessage)`. For `thread/tokenUsage/updated`, use only `last` as per-request usage and deduplicate identical `total` snapshots within the dispatch. If no usage notification arrives, successful terminal handling records all four fields as null. Do not treat `thread.tokenUsage.total` as a turn delta or monetary cost.

The adapter does not modify `~/.codex` or user configuration. Actual startup options for CODEX_HOME, configuration overrides, and `--disable` were checked offline with local `codex-cli 0.153.4`. System/organization policy may override local options. Real-model behavior and final tool exposure under managed policy were not verified; offline fixtures are not end-to-end external-system read-only acceptance.

A's RPC/terminal waits use monotonic time; unrelated frames and clock rollback do not refresh limits. `adapter.close()` reclaims connections spawned by this instance and fails explicitly if child exit is unobserved. `hasActiveResources(sessionId)` remains true, blocking owner reconciliation release. Retain failed-cleanup handles for another close attempt. Handle only owned spawned processes: no process scanning or killing by persisted PIDs after restart. Resource exit is not a business terminal event.

## Compatibility boundaries and sources

| Integration | Wiring reference | Dependency / validation boundary |
| --- | --- | --- |
| Claude Agent SDK | `@anthropic-ai/claude-agent-sdk` **0.3.241** as the declared minimum API baseline | Optional peer range **`>=0.3.241 <1`**; not pinned by the repository and not a claim that every version in the range was tested |

The [configuration reference](https://developers.openai.com/codex/config-reference) covers feature/MCP settings and project trust; [configuration basics](https://developers.openai.com/codex/config-basic) explains configuration loading. Implementation fields were compared with v2 types generated by local `codex-cli 0.153.4` using `codex app-server generate-ts --out /private/tmp/agent-orch-codex-schema`. Regenerate and run contract tests for other versions. stdio is the default; experimental WebSocket is not enabled.
- No paid Claude or Codex model was contacted. Actual account login, authorization, network, MCP, and third-party gateway end-to-end operation remain unverified.
