# SPEC-0004: Scheduling and runtime reliability fixes

Date: 2026-09-20. Baseline: `dbad085` (originally `bba83e5`, with an identical file tree after author correction). Scope: historical scheduling scans, host shutdown configuration, TypeScript request waits, and Claude cleanup confirmation. Preserve SPEC-0003-A2 A/Q/R, human acceptance, and unknown-outcome semantics.

## Goals and non-goals

Do not refactor the engine architecture, implement GC/archival, or change event pagination, approval clocks, Codex frame limits, or other P2 items. Do not invoke paid models or present offline tests as real-provider acceptance.

## Numbered acceptance criteria

- **AC-R01 Scheduling performance:** Select only queued candidates from the durable task table, preserving creation order. Each historical nonqueued task must not trigger a full dispatch scan. Rebuildable indexes must preserve storage schema 2 business semantics. Admission still uses durable A/Q/R and conflicts, with a recheck inside the actual dispatch transaction; stale memory counts cannot authorize excess dispatches. Continue checking later candidates after one cannot dispatch. Verify scan work and actual creation latency at multiple offline history sizes, and regress concurrency limits, session serialization, restart, and unknown quarantine.
- **AC-R02 Shutdown configuration:** Both Unix and stdio hosts honor explicit shutdown.mode and shutdown.timeoutMs for SIGINT/SIGTERM. Without configuration, preserve each entry point's existing defaults. Unexpected owner EOF retains separate bounded interrupt cleanup, not active drain. Drain waits for work; interrupt requests a stop. Timeout explicitly reports SHUTDOWN_INCOMPLETE, retaining the host and operationId for continuation without claiming success or escalating drain automatically. Verify both transports and modes with actual temporary child processes and fake providers.
- **AC-R03 Request deadlines:** Ordinary TypeScript Unix RPC requests default to 30000ms, configurable at connection creation and overridable per request. Connection establishment and initialize retain independent limits. Timeout/cancellation ends only the local wait and removes pending state, without closing a healthy connection or cancelling remote tasks. Ignore late receipts without affecting later requests. Retain method/scope/idempotencyKey for mutation recovery. Explicit task.wait total budgets remain effective, and owner shutdown request waits cover its configured shutdown budget. Test default timeout, overrides, late receipts, later requests, idempotent recovery, and nonzero CLI exit when the host does not respond.
- **AC-R04 Claude cleanup evidence:** Query.close returning, iterator.return(done:true), and AbortSignal cannot independently prove owned-child exit. Record actual processes through the official spawnClaudeCodeProcess interface and observe exit, handling owned handles only. Retain resource occupancy while any exit is unconfirmed; bounded cleanup failure yields unknown/SHUTDOWN_INCOMPLETE, and late exit may update evidence. Automatic lease release still requires matching valid terminal evidence plus local cleanup. Process exit alone must not fabricate a remote terminal. Injected factories without process observation are conservative. Tests use actual offline fixture children, not no-op close as exit proof. Update SPEC-0002's earlier assumption and affected tests.

## R04 follow-up: Owner reconciliation of unobserved resources and stalled shutdown

This increment completes R04 recovery boundaries only. It does not implement 0003-B, alter ordinary-client permissions, or introduce automatic release or a general force flag. Reuse owner-only sessions.reconcile declarations and exact targets without requiring SDK callers to migrate the wire contract.

- **AC-R04.1 Reconcile unobserved records:** A record without observed spawn still blocks automatic release. Permit an explicit owner localResources=stopped declaration only after execution observation ends, spawning is sealed, the dispatch/session/generation matches exactly, and no process was observed. Ordinary clients, stale targets, conflicting evidence, ongoing observation, and genuinely live processes cannot use this path. Adapters without the narrow interface retain their original guard. After local attestation, unknown remote execution still holds A. Both sides stopped may release only A, retaining Q/blocked when business evidence is incomplete.
- **AC-R04.2 Persist before retiring records:** Save the original target, actor, declaration, unobserved-resource disposition, and separate resource-reconciliation event. Retire the corresponding adapter record only after its transaction commits. Persistence failure, exceeded deadline, evidence conflict, or stale target leaves records and leases unchanged. Same-key retries do not retire twice or duplicate events, and cannot affect another session with the same provider or a later dispatch in this session. Manual settlement is not automatic resource_observation and cannot fabricate process-exit evidence.
- **AC-R04.3 Independent bounded cleanup:** Once cleanup begins, permanently pending or invalid Query.close/iterator.return results must not prevent owned stdin EOF/SIGTERM fallback within the original cleanupTimeoutMs total. Give the SDK half the budget, then observe fallback exit for the remainder. Missing close or synchronous/asynchronous failure permits immediate fallback. Do not depend on SDK forwarding of abortController, signal other processes, or treat signal issuance, Promise return, or deadline expiry as exit. A refusing child remains unknown after the budget; only actual late exit updates observed evidence. This budget cannot preempt synchronous code blocking the JS thread.
- **AC-R04.4 Actual-call-chain regression:** Use real offline child processes for pending/invalid close, independent signals, ignored SIGTERM/EOF, multiple owned processes, and unrelated processes. Use the actual engine/SQLite, SDK, and owner stdio to verify attestation, permissions, rollback, idempotent retry, scheduling recovery, and shutdown. Do not read login credentials or invoke paid models.
- **AC-R04.5 Cleanup during shutdown:** After an owner starts shutdown and receives SHUTDOWN_INCOMPLETE for unknown resources, the constrained sessions.reconcile path remains available. This must not reopen task creation, execution resume, or message dispatch. Continue with the original shutdown operationId after reconciliation; shutdown completes only after the actual host exits. A fully closed engine or degraded storage that has not entered owner shutdown does not gain write access through this exception.
- **AC-R04.6 Harden adapter finalization:** null/undefined from prepare retains the guard. Other non-function values or thrown errors are rejected before commit with INVALID_RUNTIME_CONTRACT, without releasing a lease or saving a successful reconciliation. Run a valid finalizer only after the attestation transaction commits. First persist the receipt as persisted with result.resourceCleanup.status=pending and unobservedResourcesReconciled=false; only successful acknowledgement changes it to completed/true and writes the resource-completion event. A synchronous throw returns RESOURCE_CLEANUP_INCOMPLETE with operationId/auditCommitted and retains the original finalizer. An explicit owner retry with the same key/payload continues it without repeating business reconciliation, calling prepare again, or affecting later dispatches. Pause new dispatches on this host while pending and resume after success, without automatic retries. If finalization ran but completion persistence failed, retry only the acknowledgement. A restart that loses the finalizer keeps an unknown receipt and reports an explicit error; a new adapter or empty memory cannot substitute for the original cleanup. Do not change resolveConflict's currently unreachable path, other P2 items, or 0003-B.

  Observe fulfillment/rejection of a contract-violating Promise without unbounded waiting. Same-key retries while it is pending must not invoke the finalizer concurrently. After rejection, the owner can explicitly retry the original function. After fulfillment, explicit continuation is still required to complete the receipt. A returning finalizer whose resource query remains active cannot report cleanup completion. A committed declaration does not mean finalization finished.
