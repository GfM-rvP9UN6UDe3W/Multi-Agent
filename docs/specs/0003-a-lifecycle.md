# SPEC-0003-A: Lifecycle implementation contract

Date: 2026-09-19. Status: implemented with passing offline regression; see [TDD and acceptance boundaries](../tdd/0003-a-evidence.md). This refines AC-A01–A06 of [SPEC-0003](./0003-policy-retention-deadlines.md). GC, automatic routing, and fork/compact/rotate are outside this increment.

[SPEC-0003-A2](./0003-a2-execution-isolation.md) subsequently separated execution occupancy from outcome quarantine and unified the development default for new turns at 1800 seconds. A2 is implemented. The 300-second defaults and unknown-outcome slot accounting below preserve the historical A baseline rather than describe the current A2 behavior.

- Engine `timeouts`: `acceptanceMs=30000`, `turnMs=300000`, `drainMs=300000`, `interruptMs=30000`, `reconcileMs=60000`, each an integer in 1..86400000 ms. Existing calls retain defaults. Control deadlines come from owner configuration; ordinary clients cannot extend them arbitrarily. SDK wait deadlines are independent.
- Persist dispatch entry time, acceptance deadline, total deadline, target generation, possible-send marker, and last evidence. Pending control `lifecycle` stores enteredAt/deadlineAt, policyVersion, kind, expectedGeneration/expectedDispatchId, and mayHaveBeenSent/lastEvidence. Use a monotonic runtime clock; restart does not reset durable deadlines.
- Watchdog timeout transactionally settles targets and related operations/messages/outbox as unknown/blocked. Continue collecting late evidence for the original turn without automatically marking success or resending. Derive isolated slots from durable unreconciled dispatches; an observation Promise returning does not release them.
- `sessions.reconcile({target,evidence,idempotencyKey})` uses the same exact target fields as control. Only the host owner with `CallContext.owner=true` may call it: embedded TS and managed-stdio Python qualify, ordinary socket clients do not. This is explicit human attestation, not automatic history inspection of either upstream runtime.
- Evidence is a serializable owner declaration: `source:"owner_attestation"`, `summary:string`, `localResources:"stopped"|"unknown"`, `remoteExecution:"stopped"|"unknown"`, `sideEffects:"resolved"|"unknown"`, `outcome:"not_executed"|"completed"|"failed"|"interrupted"|"unknown"`, and optional `result:string` (required for completed). Persist the complete declaration, summary, actor, time, and original dispatch reference. This is attributable human evidence, not independent adapter observation. Models and ordinary clients lack this permission.
- Reject a stopped-resource release while this process retains an unfinished consumer/cleanup handle. Reject conflicts between late evidence and the declaration. Local-process termination alone, or any unknown field, does not authorize business release. Once all evidence is reconciled: not_executed → paused, with explicit resume required to requeue against the original provider history; completed → save output and remain paused, with resume only requesting acceptance again; failed/interrupted → fail the task (create a separate task to continue, without replaying side effects). Preserve original unknown control history and append resolution rather than pretending it completed on time.
- Negotiate through initialize.capabilities.lifecycle={version:1,reconcile:"owner-attestation",durableDeadlines:true}. This is a compatible extension of wire 1.0: old SDKs do not invoke it; new SDKs reject reconcile if capability is absent. Older clients may ignore new optional fields. Optional JSON additions do not change schema version; restore old records with missing fields conservatively as unknown, without automatic migration/resend.
- The Claude adapter adds bounded observation and cleanup waits. Public cancellation APIs are for cleanup and must not fabricate stopped evidence. If resource closure cannot be confirmed, close returns SHUTDOWN_INCOMPLETE. Emergency host-EOF handling must be bounded and touch only owned resources.
- `RuntimeAdapter.hasActiveResources(sessionId)` is a resource guard before reconciliation release. Adapters that may retain unconfirmed cleanup resources after `execute()` ends must implement it. Claude retains unconfirmed Query handles; Codex retains its spawned connection until corresponding cleanup evidence is observed. Codex signals only its owned child-process handles. TERM/KILL each use the original `closeTimeoutMs` stage budget; never find or kill processes by a persisted PID or process name after restart.

- The [SPEC-0004 R04 follow-up](./0004-runtime-reliability.md) adds owner-only handling for Claude records where no process was ever observed. `prepareUnobservedCleanup({sessionId,dispatchId,generation})` only prepares a synchronous finalizer without side effects; run the returned finalizer only after the attestation transaction commits. Refuse if observation is unfinished, spawning is unsealed, any process was observed, or the target differs. Adapters without this narrow interface retain their original blocking behavior. This manual settlement is not automatic stop evidence. Reconciliation remains available during incomplete active owner shutdown, while new work stays rejected.

Acceptance covers controlled monotonic time, clock rollback, deadline boundaries, durable restart deadlines, late events, permission refusal, local-process-only stop refusal, non-replaying resume after reconciliation, real stdio/socket wiring, and owned-subprocess cleanup. Keep source/test changes scoped to this increment and record RED/GREEN evidence separately.
